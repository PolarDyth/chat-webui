Implement 7 UX improvements to Chatboard (chat-webui). No new dependencies, no DB schema changes (the uncommitted `description` column in schema.ts stays untouched; no drizzle push needed). All changes fit the existing flat-transcript style (plain-text metadata, hover-revealed actions).

## 1. URL-backed chat selection (fixes reload → landing, dead back/forward)
`src/components/chat/chat-workspace.tsx`:
- On mount, read `?c=<id>` from `window.location.search` and set `activeChatId` from it.
- Wrap selection: `selectChat`/`newChat`/delete-clear each push a history entry (`history.pushState(null, '', '/?c=<id>')` or `'/'`).
- Add a `popstate` listener that sets `activeChatId` from the URL.
- On first load, if the `?c=` id is not in the fetched chats list (abandoned unsaved "new chat" id), clear the param via `replaceState` and show the landing.
Pure client-side `history` API — no server round-trips, safe under `cacheComponents`.

## 2. Sidebar chat search
`src/components/chat/chat-sidebar.tsx`: add a small filter `<Input>` with a Search icon under the New-chat button. Case-insensitive title filter applied to both Pinned and Recent groups; hide a group header when it has no matches; show a muted "No matches" row when both are empty. Pure client-side.

## 3. Transcript loading state (kills the empty-state flash)
`src/components/chat/chat-view.tsx` + `chat-canvas.tsx`:
- Track `historyLoaded` (set when the initial per-chat `sync()` fetch settles — including failure, so a broken fetch can't hang the skeleton).
- When `!historyLoaded`, render 3–4 muted skeleton blocks shaped like the transcript (reuse `Skeleton`) in the `max-w-3xl` column instead of `ConversationEmptyState`.

## 4. Per-chat draft persistence
Keep a `useRef<Map<string, string>>` of drafts in `ChatWorkspace`, passed through `ChatView` to `PromptPanel` as `initialDraft` + `onDraftChange`. `PromptPanel` initializes its state from `initialDraft` (component is keyed by chat id, so it re-inits per chat), writes every change to the map, and clears the entry on send. Half-typed messages survive chat switching.

## 5. Timestamps in the metadata line
Surface each user message's `createdAt` (extend `ChatUIMessage` metadata typing / `hydrateMessages` in `src/lib/message-utils.ts` if the field isn't already hydrated) and append it as plain muted text to the existing `·`-separated metadata line in `exchange-card.tsx`. Format via `Intl.DateTimeFormat`: today → `14:05`, otherwise → `Oct 21, 14:05`.

## 6. Export chat as Markdown
New `src/lib/chat-export.ts`: serialize a chat to Markdown (`# title`, then per turn the user text and the answer with its model/usage line as a blockquote). `ChatHeader` gets a hover-consistent Download icon button that builds a Blob and downloads `<title>.md`. Client-only.

## 7. Edit user message + resend (largest item)
- `exchange-card.tsx`: Pencil action on the user turn's hover toolbar → inline textarea with Save/Cancel.
- Client (`chat-view.tsx`): on save, truncate messages to before the target turn (`setMessages(before)`), then `sendMessage({ text: edited }, { body: { mode, model, editingOf: targetMessageId } })` — the SDK appends a fresh user message and streams a new answer.
- Server (`src/app/api/chat/route.ts`): when body has `editingOf`, reuse the existing regenerate plumbing — update the target user row's `parts` with the new text and run the existing `deleteMessagesAfter` so stale rows are removed; snapshot the previous assistant answer into the new assistant row's `variants` for parity with regenerate.
- Truncate the streamed user text same as normal sends.

## Out of scope (listed for later)
