# AI chat-description tool

Generate a short AI description from each chat's title (non-streaming: one request, complete result), then animate it into the chat header under the title once it arrives.

## Decisions (defaults since no answers returned)
- **Placement**: muted `text-xs` line under the title in the chat header.
- **Trigger**: after a new chat's first answer completes, plus backfill when opening an older chat that has none. Renaming a chat clears the description so it regenerates from the new title.
- **Animation**: word-by-word blur→sharp rise (~40ms stagger) with the header height easing open. No placeholder while generating — the line only exists once the result is in.
- **Model**: the app's free-model chain (`openrouter/free` + top free fallbacks), so cost is ~zero; same BYOK key resolution as the chat route.

## Changes

1. **`src/lib/db/schema.ts`** — add `description: text('description')` (nullable) to `chats`. Then run `npx drizzle-kit push` to sync the local DB.

2. **`src/lib/types.ts`** — add `description: string | null` to `ChatSummary`.

3. **`src/lib/db/queries.ts`** — extend `updateChat`'s patch type with `description?: string | null`, and add `setChatDescription(userId, chatId, description)` that writes only that column (no `updatedAt` bump, so generating a description for an old chat doesn't reorder the sidebar).

4. **`src/lib/ai/prompts.ts`** — add a description system prompt ("given a conversation title, reply with one very short description of what the chat is about, ≤6 words, no quotes/preamble, match the title's language") and a small `cleanDescription()` (trim, strip wrapping quotes, cap length).

5. **New route `src/app/api/chats/[id]/description/route.ts`** — `POST`, following the existing `[id]/route.ts` conventions (async params, UUID guard, `getCurrentUserId()`, ownership via `getChat`, API key from settings or env with `missing-key` error, `dbNotConfigured` guard). Rejects with 409 if the title is still `'New chat'`. Runs non-streaming `generateText` from `ai` over the free-model candidates (simple try/catch loop, ~40 max output tokens), persists via `setChatDescription`, returns `{ description }`.

6. **`src/app/api/chats/[id]/route.ts`** — in `PATCH`, when the title changes also set `description: null` so a renamed chat regenerates.

7. **`src/hooks/use-chats.ts`** — add `setDescription(id, description)` (local state update, like `rename`; the server already persisted it).

8. **`src/components/chat/chat-view.tsx`** — `useChatView` gains description state (initialized from `chat.description`, synced when the prop changes) and a generation effect: fires when the chat has a real title, no description, and nothing is in flight (ref guard) — covering both the post-first-answer moment (after the existing `onChatsChanged()` on `status → 'ready'`) and opening a description-less chat. On success: `setDescription` locally (triggers the animation) and refresh the sidebar.

9. **`src/components/chat/chat-workspace.tsx`** — placeholder chat object gets `description: null`; pass `setDescription` down to `ChatView`.

10. **New `src/components/chat/chat-description.tsx`** — `motion/react` component: `AnimatePresence` + staggered word spans (opacity 0→1, y 4→0, blur 3px→0) wrapped in a height 0→auto container so the header eases open. Mounts only when text exists (nothing shows while generating). Follows the `motion.create` caching pattern already used in `shimmer.tsx` if needed.

11. **`src/components/chat/chat-header.tsx`** — wrap title + description in a `flex min-w-0 flex-1 flex-col gap-0.5` column inside the existing header row.

12. **`src/components/chat/chat-sidebar.tsx`** (type-only touch if needed for the new `ChatSummary` field).
