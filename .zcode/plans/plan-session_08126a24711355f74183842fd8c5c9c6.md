# Rework: AI-generated chat titles (not descriptions)

I misread the original request. The AI text should **replace the chat title itself**, the call should fire **the moment the first message is sent** (not after the answer), and the UI should update **as soon as the title model returns its complete (non-streamed) result**. The description-below-title feature gets removed.

## Mechanism
The title generation rides the existing chat stream: when the first message arrives, `/api/chat` starts the AI title call immediately, concurrent with the answer. The heuristic title (truncated first message) is pushed through the open stream right away as a transient `data-title` part, so the header shows a real title instantly. When the AI title finishes (~2–7s, typically mid-answer), the server persists it and pushes a second `data-title` part down the still-open stream — the client animates it into the title at that exact moment. Same pattern as the existing `data-fallback`/`data-cost` parts; no polling, no extra fetch.

## Changes

**Remove the description feature**
1. Delete `src/app/api/chats/[id]/description/route.ts` and `src/components/chat/chat-description.tsx`.
2. Remove `description` from: `ChatSummary` (types.ts), the `chats` schema column, `setChatDescription` + patch field (queries.ts), the PATCH title-change clearing (chats/[id]/route.ts), the workspace placeholder, and the header column.
3. DB: hand-apply `ALTER TABLE chats DROP COLUMN description` (drizzle-kit push hangs on this machine).

**AI title generation**
4. `prompts.ts`: replace description exports with `TITLE_SYSTEM_PROMPT` (≤6 words, match language, no quotes/preamble), `TITLE_EXAMPLES` (few-shot: first message → title), `cleanTitle()` (same hygiene: strip quotes, cap length, reject meta-commentary).
5. New `src/lib/ai/title.ts`: `generateChatTitle({ apiKey, defaultModel, firstUserText })` — walks the free-model chain (`openrouter/free` → user's default → top 6 text-capable free models), non-streaming `generateText`, 512 max tokens, returns the cleaned title or null.
6. `src/app/api/chat/route.ts`: on first send, kick off `generateChatTitle` immediately; write the heuristic `data-title` part at stream start; on completion — guard against clobbering a rename made mid-generation (re-check the row's title), persist, write the AI `data-title` part (swallow the write if the stream already closed; the DB row is updated regardless).
7. `types.ts`: add `title: { title: string }` to `ChatDataTypes`; drop `description` from `ChatSummary`.

**Client**
8. `use-chats.ts`: `setDescription` → `adoptTitle(id, title)` (local store update; server already persisted).
9. `chat-view.tsx`: `onData` handles `data-title` → `adoptTitle` (fires mid-stream, exactly when the model returns). Remove all description state/trigger logic.
10. New `src/components/chat/chat-title.tsx`: animated `h1` keyed by title text — on change it remounts and animates word-by-word (blur → sharp rise, ~40ms stagger, truncate). Animation suppressed on first mount so opening a chat doesn't replay it.
11. `chat-header.tsx`: `<ChatTitle title={title} />` replaces the static h1.
12. `chat-workspace.tsx`: placeholder without `description`, pass `adoptTitle` down.

Old chats keep their heuristic titles (no backfill — can add later if wanted).
